# 前端组件与交互规范 / Frontend guidelines

本文件是 `dsh-plugin-project` 与 `dsh-project-desktop` 的通用前端约束，并包含插件页面的具体约定。修改组件、样式、表单、弹窗或侧栏前必须阅读。Shell 的窗口及原生流程还须遵守其 [前端补充规范](https://github.com/admintertar/dsh-project-desktop/blob/master/docs/frontend-guidelines.md)。

通用规则统一在本文件维护，Shell 文档维护窗口特有规则；变更跨仓库约定时同步检查两边的引用与适用范围。组件能力以插件 `upstream.json` 与 Shell `upstream.lock.json` 固定的 stable 组合为准，升级时重新核对，不能假定当前未导出的组件永远不可复用。

English summary: both repositories must reuse pinned official components, behavior, locale and theme. Shared adapters own settings rows and long modals; scrolling must not shift content. Private-source adaptations require attribution and upgrade review. UI changes require native visual and interaction checks in addition to automated checks. The detailed requirements below apply to both repositories unless marked as plugin-specific.

## 1. 官方组件及完整行为

1. 先检查 `@deepseek-ai/dsh-client-ui-primitives` 的实际导出，再查看固定版本中对应的官方页面。官方已有可复用的输入框、按钮、下拉菜单、开关、弹窗、折叠区、提示或图标时，直接使用。
2. 基础颜色、字号、尺寸、圆角、悬停、焦点、禁用和键盘交互跟随官方组件。项目 CSS 主要负责宽度、排版、间距和滚动约束；不得为了视觉近似另写一套控件，也不得用全局选择器覆盖官方基础组件。
3. 官方已有完整功能时，复用其入口、配置保存、确认与取消、实际窗口及生命周期。接入边界可以增加项目范围限制，不能只借用名称和文案后自行重写交互。
4. 只有官方未导出所需能力或无法直接复用时，才做最小组合或源码适配。注明官方模块/组件、适配原因和版本依据，保留第三方声明；不修改固定官方源码或构建后的上游 bundle。
5. 升级时逐项检查适配；官方提供可用导出后优先改为直接引用。当前 Textarea、Radio、Checkbox 没有公开 primitive，已有适配须沿用官方主题变量、语义与交互，并注明来源。

来源和许可记录见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。规范描述的是开发与验收要求，不代表每个现有页面已完成所有状态的验收。

## 2. 组件选择与共享封装

插件的共享适配集中在 [ProjectControls.tsx](../src/client/ProjectControls.tsx)，布局与注明来源的样式在 [styles.ts](../src/client/styles.ts)。新增页面优先复用这些封装，避免各面板复制一份。Shell 通过自己的固定插件适配入口复用，不复制插件源码或直接依赖其可变工作目录。

| 场景 | 必须使用的组件或参考实现 |
| --- | --- |
| 普通输入、按钮、提示、图标 | 固定官方 primitives 的相应导出 |
| 下拉选择 | `ProjectSelect`，组合官方 `Menu`、`Button` 与箭头；参考设置 → 通用设置 → 语言的 `LanguageRow` |
| 设置行 | `ProjectSettingRow`，参考官方设置行；长编辑器用 `stacked` 布局 |
| 添加条目 | `ProjectAddButton`，采用设置 → 模型 → 添加提供方的 `ModelsSection` 加号与虚线按钮 |
| 设置型开关 | `ProjectToggleRow` / `ProjectSwitch`，组合官方 `Switch`，最小适配 Desktop 通知开关的外观 |
| 长内容设置弹窗 | `ProjectScrollableModal`，由官方 `Modal` 提供标题、正文和操作区 |
| 短确认、短提示、单字段弹窗 | 直接使用官方 `Modal`；已有完整官方原生窗口时复用该窗口 |
| 成组高级配置 | `ProjectSettingsCard`，参考设置 → 插件 → Subagent 的私有 `PluginCard` |
| 普通折叠区 | `ProjectDisclosure`，复用官方 `DisclosureRow` |

封装只承接共用的布局与适配，不接管业务状态。焦点、禁用、菜单选择等交互继续由官方组件负责；需要补足的适配行为必须覆盖键盘与关闭后的焦点返回。

## 3. 设置表单与弹窗

- 桌面宽度下每项独占一行，左侧标题和说明、右侧操作控件，同类输入框宽度一致，行间使用官方主题的细分隔线。窄容器自动切换为上下排列。
- JSON、多行文本、环境变量和请求头等长内容采用标题在上、编辑区全宽的布局。不要把无关设置排成双列问卷式表单。
- 长设置弹窗统一使用 `ProjectScrollableModal`。标题和底部操作固定，正文只建立一个纵向滚动区，子表单不得再嵌套纵向滚动。
- 正文遵循官方 `SettingsRoot.options` 的左右 24px 有效留白。滚动条占用既有右侧留白，不额外挤压表单。菜单通过官方能力在弹窗外层显示，不能被正文裁切。
- `ProjectSettingsCard` 默认折叠，保留字段草稿；展开区与标题区使用细分隔线。在弹窗中共用底部保存操作，不额外增加卡片级保存按钮。
- 设置开关仍用普通设置行，不单独增加背景、边框和圆角卡片。标签描述功能，例如“启用服务”，不要用固定的“已启用”充当功能名称。

24px 是上述设置弹窗的有效留白要求，不是所有页面或窗口的统一 padding。Shell 欢迎/创建窗口采用其专门的布局约定。

## 4. 滚动、留白与自适应

- 任何可能滚动的页面、弹窗、侧栏、列表或卡片区域，都不能因滚动条出现、消失或内容切换改变内容宽度和横坐标。
- 默认使用 `scrollbar-gutter: stable`。需要对称留白时，从既有右 padding 中扣除 `--dsh-scrollbar-width`，让滚动槽落在原留白内，避免在预留槽之外再叠加一份滚动条空间。
- 滚动归属必须明确：长弹窗只有一个正文滚动区；任务列表与详情可以分别滚动，因为它们是独立区域。不要给这类页面的外层再加一个整页纵向滚动区。
- 长名称、路径、地址和工具列表必须能换行或在明确的内容区内滚动；表单和普通页面不得产生意外横向溢出。
- 插件页面、侧栏、列表与长弹窗的滚动条空闲 800ms 后以 180ms 淡出：真实 scroll 事件立即显示，拖动滑块期间保持可见，减少动态效果偏好下直接隐藏。仅改变可见性，不移除稳定槽、不改变布局。官方聊天、官方侧栏与官方弹窗保持官方常驻滚动条，Shell 引导窗口的同类行为见其补充规范。
- 滚动容器集中在 [scrollbar-auto-hide.ts](../src/client/scrollbar-auto-hide.ts) 登记：该清单同时驱动控制器与生成的滚动条样式，新增可滚动区域必须登记，`tests/client-styles.test.ts` 会校验每个 `scrollbar-gutter:stable` 容器与清单一致。
- 验收覆盖无溢出、有溢出、动态内容切换、窄窗口和滚到底部；检查固定操作区是否可见、首尾内容是否完整。

## 5. 主题、语言与侧栏

- 使用官方 locale 服务和主题变量，中文统一使用“新会话”。可见文案、错误、空状态、提示及无障碍标签一并检查中英文，不在各组件中自行判断系统语言。
- 侧栏复用官方插槽、结构和玻璃材质，不在插件 CSS 中增加不透明背景覆盖材质。明暗模式与窗口材质分别沿用官方机制。
- 应用级共享明暗偏好由 Shell 的 Workbench 管理，并保存于应用 userData。所有正常项目窗口的官方 `ui-theme.preference` 与 Electron `nativeTheme.themeSource` 同步，插件不得独立覆盖或在关闭时还原共享值。
- 首次沿用第一个完成主题接入的项目偏好；之后新开、重启、切换 Profile 都以共享值为准。字体大小、语言及其他项目设置保持各自范围，安全模式维持 Shell 已有的隔离边界。
- 检查浅色、深色、跟随系统、多窗口实时切换、重新打开、折叠侧栏，以及应用主题与系统明暗不一致的情况。

## 6. 插件页面的具体约定

### 会话与任务预览

项目会话区以官方 `WorkspaceBrowser` 的 `FlatList`、Search、`SessionNodeItem` 和 CSS 为适配来源，只移除 Workspace 分组/目录操作并增加 Project-root 边界。

任务文件在窗口最右侧的完整侧栏预览，复用官方 `RightbarSeat`、展开按钮、`TextPreview` 和文档渲染器；宽度由官方 AppFrame 管理。不得在任务页内另造第三列或自行拼装 Markdown/CodeBlock 预览。

任务列表与详情独立滚动。离开任务页再返回时保留任务、筛选、分页和列表/详情状态；窄窗口只能展示列表或详情之一时，双向返回入口位置固定。切换任务不要求关闭文档侧栏，不自动替换已打开文档。任务与聊天的侧栏状态独立；收起保留标签和已读内容，资料标签展示当前任务全部资料与产物，选中文件在当前分栏打开。

### MCP 与工具卡片

- MCP 设置弹窗使用紧凑宽度，当前基线为 660px，并保留设置行的左右布局和窄窗口自适应。
- 工具页参考官方 `AgentPresetSection` 卡片的圆角、细边框、间距、等高网格与四行摘要。通过官方按钮和弹窗查看完整说明，不增加无意义的选中或执行操作。分组顺序为项目工具、MCP 工具、DSH 与插件工具。
- MCP 服务卡片共用上述 `auto-fill` 网格（轨道宽度 `min(363px, 行宽的一半)`，`1fr` 继续拉伸）；行宽不足两个 363px 卡片时按半行收窄，任何窗口宽度都至少两列，不出现单卡撑满整行。同一行等高，各行按内容独立计算，长地址或错误不应撑高所有行。
- 服务卡片正文紧凑排列服务名、开关、连接状态和工具列表，命令/地址与本机配置提示尽量共用一行，空间不足时换行。当前基线为正文 6px 行间距、12px/10px 上下内边距。
- 编辑/删除位于底部细分隔线下，使用带官方 Tooltip 的图标按钮。卡片本身不是选择按钮，不套用预设的选中态。
- 工具名称直接显示，取消“工具数量 → 点击展开”。工具区固定两行高度，当前为 40px；多个工具在区内滚动并支持键盘，无工具时保留区域。长文本可换行或滚动，窄窗口保持单列。

这些数值是当前页面的具体基线，不应推广成所有卡片或控件的通用尺寸。

## 7. 实施与验收

每次 UI 修改先确认官方实现与复用入口，再在既有共享封装或页面布局内完成改动。新增私有适配要记录来源和原因；Shell 的私有接口还须登记到其架构文档。升级时同时核对两仓库固定组合，不以旧缓存仍可运行作为兼容依据。

验收按本次改动涉及的范围执行，并记录实际平台、版本及未覆盖项：

- 中英文、浅色/深色、跟随系统；长文案与空状态。
- 默认、悬停、焦点、禁用、加载、成功和失败状态。
- Tab、Enter/Space、Escape、方向键等相关键盘操作，菜单关闭/弹窗关闭后的焦点，以及图标按钮的可访问名称。
- 窄窗口、长文本、滚动条出现/消失与空闲淡出（滚动时立即显示、停止 800ms 后透明、拖动滑块期间保持可见）、动态切换与滚到底部；无裁切、位移或意外横向溢出。
- 表单取消、草稿保留、重复提交阻止；异步操作失败后恢复可操作状态。
- 涉及 Shell 原生功能时，在真实 Electron 窗口核对官方界面的确认、取消与实际行为；共享主题改动还需多窗口验收。

源码变更执行 `yarn run check`，原生与集成检查按 [开发说明](development.md) 及 Shell 的检查入口选择。测试通过或构建成功不能替代真实界面的视觉与交互验收；没有运行的检查必须如实注明。仅文档改动检查内容、链接和差异即可。
